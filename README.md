## Навіщо

В агенції щодня треба звітувати, скільки часу пішло на кожен проєкт. До вечора половина дня стирається з пам'яті: що це було о 11:40 — ТЗ, звіт чи листування з клієнтом? Таймери «старт/стоп» теж не рятують: їх забувають вмикати.

Bison Time Checker (BT) знімає цю роботу. Він працює у фоні, сам розкладає день по проєктах і до вечора має готові цифри для звіту: години, хвилини та чернетку коментаря.

**Для кого.** Створено для співробітників Inweb, але підійде будь-кому, хто веде кілька клієнтських проєктів одночасно: SEO-спеціалістам, маркетологам, контент-менеджерам, проджектам.

## Що вміє

- **Сам визначає проєкт.** Проєкт — це домен клієнта. BT знаходить його в заголовку активного вікна: у назві документа, задачі, файлу чи вкладки браузера.
- **Документи за конвенцією.** Назва `shop.com.ua / ТЗ №5 / Виправлення помилок` одразу дає проєкт, документ і задачу.
- **Таск-менеджери.** Задача з доменом клієнта в назві йде в цей проєкт, а планувальник чи списки задач — у проєкт, над яким ти працював поруч у часі.
- **Інструменти SEO.** Краул у Screaming Frog (`https-site-com-ua-`) або URL у заголовку вікна теж визначають клієнта.
- **Нові клієнти без налаштувань.** Новий домен у назві документа чи задачі сам стає проєктом.
- **Звіт за хвилину.** Картка кожного проєкту показує «2 год 35 хв», як у формі звіту, рядки з яких склався час і чернетку коментаря з кнопкою «Копіювати».
- **Чесний час.** Простій без миші й клавіатури (а ніч з увімкненим комп'ютером — тим паче), заблокований екран і сон не рахуються, а дзвінок у Meet, Zoom чи Teams простоєм не вважається. Переключення коротші за 5 с не записуються. Клік по рядку показує, коли саме йшов час. Будь-який рядок можна вимкнути, а роботу поза комп'ютером додати вручну.
- **Клавіатура.** Tab, Enter, `Ctrl+1…7` по розділах, `Alt+←/→` по днях, `Ctrl+Shift+C` — звіт за день у буфер.
- **Пауза.** Кнопка або `Alt+Shift+P` з будь-якої програми. Поки облік на паузі, іконка помаранчева, тож забути про неї складно.
- **«Завершити роботу».** Облік зупиняється до ранку й сам вмикається о 05:00, а вікно дня відкривається з підсумком для звіту.
- **Сучасний інтерфейс.** Material 3 у кольорах Inweb: вікно дня біля трею для швидкого погляду й головне вікно з меню зліва — Сьогодні, Дашборд, Проєкти, Правила, Облік, Довідка, Про BT. «Копіювати звіт» забирає всі проєкти дня одним текстом.
- **Дашборд.** День, тиждень, місяць: весь записаний час, проєкти, «Інше» і частка проєктів. Діаграми по програмах (скільки забирає месенджер) і окремо по браузеру: Google Docs, Meet, Planfix, YouTube тощо. Клік по дню відкриває його для виправлень.
- **Оновлення в один клік.** BT раз на добу перевіряє нову версію й завантажує лише змінені файли. Кожне оновлення підписане й перевіряється перед встановленням.
- **«Інше» по програмах.** Усе, що не потрапило в проєкти, розкладено по програмах з часом на кожну: видно, скільки за день пішло на месенджер чи браузер. Усередині — записи в порядку часу, щоб згадати, що ти шукав. Перемикач «Хронологічно» показує весь ланцюжок дня. Будь-який запис переноситься в проєкт у два кліки, а цілу пачку — вибором (Shift+клік бере діапазон) і одним «→ Проєкт»; BT ще й запропонує правило, щоб наступного разу це сталося само.

## Як BT визначає проєкт

| У заголовку вікна | Куди йде час |
| --- | --- |
| `shop.com.ua / ТЗ №5 / Виправлення помилок` (документи Google і все, назване так само) | shop.com.ua, рядок «ТЗ №5 · Виправлення помилок» |
| `Inweb / Навчання / GEO` | внутрішній проєкт Inweb |
| Домен відомого проєкту будь-де: `shop.com.ua - SEO-комплекс`, `shop.com.ua outreach.xlsx` | shop.com.ua |
| Заголовок починається з нового домену: `newclient.ua - SEO-комплекс` | новий проєкт newclient.ua створюється сам |
| URL або краул Screaming Frog: `https://site.com.ua/…`, `https-site-com-ua-` | site.com.ua (новий проєкт — після хвилини роботи) |
| Таск-менеджер без домену в назві: планувальник, списки | проєкт, над яким працював у межах 15 хв до або після |
| Заголовок без проєкту, але адреса вкладки на сайті клієнта: `… \| Shop` на `shop.com.ua`, Search Console з ресурсом `sc-domain:shop.com.ua` | shop.com.ua (лише відомі проєкти) |
| Твоє правило: «Looker Studio» → shop.com.ua, figma → shop.com.ua | вказаний проєкт |
| Усе інше: месенджери, пошта, сайти без домену клієнта в заголовку | «Інше»: у звіт не йде, переноситься вручну |

Адресу вкладки BT читає в Chrome, Edge, Brave, Opera й Vivaldi через спеціальні можливості Windows (як екранні читачі), без розширення в браузері. У Firefox працює лише заголовок. Сторінки без домену клієнта ні в заголовку, ні в адресі (таск-менеджер, внутрішні інструменти) йдуть за контекстом або в «Інше», звідки їх переносять вручну чи правилом.

## Як користуватися

1. Завантаж `BisonTimeChecker-…-win-x64.zip` з [Releases](https://github.com/iEuegene/Bison-Time-Checker/releases/latest).
2. Розпакуй папку `BisonTimeChecker` у постійне місце й запусти `BisonTimeChecker.exe`. Встановлювати нічого не треба, .NET уже в папці.
3. Програма з'явиться в треї й надалі стартуватиме разом з Windows. Клік по іконці відкриває день.
4. Наприкінці дня перенеси в звіт години й хвилини кожного проєкту, скопіюй коментар і натисни «Внесено у звіт». Велика цифра вгорі показує, скільки ще лишилося внести; внесені проєкти сірі й опускаються вниз. Якщо над внесеним проєктом ще працювали, він показує «+N хв» і рядки, яких у звіті ще немає. Помилкову дію можна відмінити з плашки внизу.

Порада: називай документи за схемою `домен / документ / задача`. Тоді BT не помиляється взагалі.

Детальна інструкція є в самій програмі: пункт **Довідка** в меню головного вікна. Список змін і правова інформація — у пункті **Про BT**.

> Програма поки не підписана сертифікатом. Windows SmartScreen може попередити про невідомого видавця: «Докладніше» → «Виконати в будь-якому разі».

**Оновлення:** головне вікно → **Про BT** → «Перевірити оновлення» → «Оновити». Коли вийшла нова версія, на пункті «Про BT» з'являється помаранчева крапка. BT завантажить лише змінені файли й перезапуститься. Якщо версія вийшла без файлів для оновлення, BT підкаже завантажити її вручну. Тримай папку там, куди можна писати (не в Program Files). Твої дані лежать окремо й нікуди не зникнуть. Версії до 1.2.0 оновлюються вручну: вийди з BT, заміни папку, запусти.

## Приватність

- **Нічого не надсилає.** Ні на сервер, ні в аналітику. Єдиний мережевий запит — перевірка оновлень на GitHub (раз на добу або за кнопкою), її можна вимкнути.
- Усе зберігається локально в `%LOCALAPPDATA%\BisonTime`: JSON-файл на кожен день і налаштування.
- З адреси вкладки береться лише домен (без шляху й параметрів) і, для сервісів на кшталт Serpstat чи GA4, номер проєкту — щоб правило могло прив'язати його до клієнта. Вимикається в налаштуваннях обліку.
- Заголовки вікон зберігаються 7 днів, дні з коментарями — 30 днів, цифри для дашборда (хвилини по проєктах, програмах і сервісах, без назв вікон) — рік.
- BT не читає вміст вікон і не перехоплює клавіатуру. Простій визначається за системним часом останнього вводу.

## Для розробників

```
BisonTime.Core/    логіка без Windows API: розбір заголовків, трекер, звіт, сховище
BisonTime.App/     WPF-програма: трей, активне вікно, простій, гаряча клавіша, інтерфейс, довідка
BisonTime.Tests/   тести ядра без залежностей: dotnet run --project BisonTime.Tests
tools/ReleaseTool/    маніфест і підпис оновлень (ECDSA P-256) для релізу
tools/make-icons.py   іконки
```

Збірка — GitHub Actions на Windows. Кожен push у `main` прогоняє тести, збирає програму й публікує zip у Releases. Разом із zip у реліз ідуть `manifest.json` (шлях, розмір і SHA-256 кожного файлу) та його підпис. Самі файли під іменами-хешами лежать в одному службовому релізі `update-files`: туди довантажуються лише нові, а непотрібні прибираються. Програма порівнює маніфест зі своєю папкою й качає лише різницю. Приватний ключ підпису живе тільки в секреті `BT_SIGNING_KEY`, публічний — у `BisonTime.App/UpdateKey.cs`. Без секрету реліз виходить як prerelease, і програма його не бачить. Версія .NET зафіксована в workflow, щоб оновлення не тягнули весь рантайм. Локально на Windows:

```
dotnet publish BisonTime.App -c Release -r win-x64 --self-contained -o out/BisonTimeChecker
```
